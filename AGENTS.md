# AGENTS.md — филогения Taraxacum по пластомам и ITS

## 0. Цель и образ результата

Проект изучает родственные связи видов Taraxacum. Мы сравниваем дерево по
полным пластомам с деревом по ITS и связываем обе топологии с метаданными
образцов, с их географией и со структурой пластома (длины LSC, SSC, IR).
Деревья уже построены в IQ-TREE. Работа агента — визуализация и
сопоставление, а не новый анализ.

В конце работы в проекте существуют:
- `results/viz/plastome_tree.pdf` — дерево пластомов с поддержками узлов
  (SH-aLRT/UFBoot);
- `results/viz/its_tree_metadata.pdf` — дерево ITS, листья окрашены по
  метаданным;
- `results/viz/tanglegram.pdf` — соответствие листьев двух деревьев;
- `results/geo/coordinates_found.csv` — координаты образцов с источником
  каждой точки; `results/viz/samples_map.pdf` — карта образцов;
- `results/viz/plastome_tree_lsc_ssc_ir.pdf` — длины LSC/SSC/IR рядом с
  деревом пластомов, образцы с отклонениями отмечены;
- скрипт каждого рисунка в `scripts/` и запись о каждом прогоне в `diary.md`.

Ничего больше создавать не надо. Каждый пункт — отдельная задача в `tasks/`
(раздел 8), задачи выполняются по порядку списка.

Учебная задача курса (ДЗ 1): статистика трёх FASTA, результат —
`results/hw1/fasta_stats.csv`. Задача в `tasks/`.

## 1. Критерий готовности

Задача выполнена, когда выполнено её «Готово, когда» в `tasks/` и пройдена
проверка. Вызови проверку сам перед окончательным ответом.

- Статистика FASTA: `python3 checks/check_hw1_fasta.py` возвращает 0.
- Рисунок дерева: число и имена листьев на рисунке совпадают с
  `.treefile`; каждый лист сопоставлен строке метаданных или внесён в
  список несопоставленных в «Итоге» задачи.
- Карта: у каждой точки есть источник в `coordinates_found.csv`; точки без
  источника на карте отсутствуют.
- LSC/SSC/IR: значения на рисунке совпадают с `ir_boundaries.csv` для трёх
  образцов, названных в «Итоге».

«Выглядит правильно» критерием не является: рисунок смотрит исследователь.

### Чего агент не может знать сам

- Основные деревья — из `results/*_20261015/`. Деревья в `tarax/` — старые
  прогоны, их не использовать.
- В метаданных нет столбцов секции и плоидности: окраска — по `Sp_name` и
  `Location`. Секцию не выводить из названия вида.
- Координаты есть у 59 образцов из 72. Остальные искать только по номеру
  образца (accession, voucher) в GenBank, BOLD, GBIF; не нашлось — пусто.
- Пластомы кольцевые: разные старт, ориентация SSC и запись IR не являются
  структурной вариацией, пока последовательности не приведены к одному виду.
- Видовая идентификация образцов не подтверждена; пропуск в метаданных не
  означает отсутствия признака.
- Какое дерево основное и как трактовать конфликт пластом/ITS, решает
  исследователь.
- В кратком отчёте ДЗ 1 порядок образцов: NC_032056.1, KU361241.1, KU736960.1.

## 5. Протокол работы

Режим работы: ReAct — после каждого рисунка запусти проверку из раздела 1.

- Одна задача — одна сессия. Новый рисунок — отдельный скрипт в `scripts/`.
- В начале скрипта: откуда данные, чем проверен, где используется.
- Красная проверка — исправь скрипт до следующего шага. Коммит после
  пройденной проверки.

## 8. Граф проекта

- Схема: `ontology.yaml`; заметки классов: `ontology/<Класс>.md`.

- Статус `принята` ставит только пользователь своими словами в сессии.
- Новые классы онтологии — только с согласия пользователя.
